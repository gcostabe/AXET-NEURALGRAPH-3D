## 4. Regras de Negócio, Especificações Funcionais & Processos

### Regras e comportamento identificados

1. A tabela `G2000510` representa dados de **processos massivos**.
2. `COD_CIA` é obrigatório e representa a companhia.
3. `FEC_TRATAMIENTO` é obrigatório e representa a data em que o processo massivo é realizado.
4. `NUM_ORDEN` é obrigatório e representa o número do processo massivo.
5. `TIP_MVTO_BATCH` é obrigatório e representa o tipo do processo massivo.
6. `TXT_ALIAS` não é obrigatório e permite informar um nome atribuído ao processo.
7. `TIP_SITU_FILTRO` é obrigatório e representa a situação do movimento.
8. Durante a operação, `TIP_SITU_FILTRO` pode assumir múltiplos valores conforme o momento do processamento:
   - `2-Filtrando`
   - `3-Ya filtrado`
9. `NOM_PRG_EXCEPCION` não é obrigatório e corresponde a um procedimento de exceção.
10. `MCA_RECALCULA_FECHA` é obrigatório e indica se deve ser utilizada como base uma data já calculada ou se a data deve ser recalculada.
11. `TIP_FECHA_BASE` não é obrigatório e indica com base em qual data ocorrerá o recálculo da data.
12. `COD_USR` é obrigatório e identifica o usuário que atualizou a linha.
13. `FEC_ACTU` não é obrigatório e representa a data de atualização da linha.
14. `TXT_MCA_PROCESO_ESTANDAR` não é obrigatório e aplica-se ao processo padrão.
15. `IDN_PROCESO_PERSONALIZADO` não é obrigatório e representa o identificador do processo massivo personalizado.

> **Nota de Análise:** A fonte não define os domínios completos dos valores de `TIP_MVTO_BATCH`, `MCA_RECALCULA_FECHA`, `TIP_FECHA_BASE`, `TXT_MCA_PROCESO_ESTANDAR` ou `IDN_PROCESO_PERSONALIZADO`.

## 6. Bateria de Perguntas & Respostas para RAG (FAQ Sintético)

### P1: Qual tabela armazena os dados de processos massivos descritos no documento?
**R:** A tabela identificada no documento é `G2000510`, cuja descrição é `PROCESOS MASIVOS`.

### P2: Quais campos obrigatórios são identificados para um processo massivo na tabela `G2000510`?
**R:** O documento marca como obrigatórios os campos `COD_CIA`, `FEC_TRATAMIENTO`, `NUM_ORDEN`, `TIP_MVTO_BATCH`, `TIP_SITU_FILTRO`, `MCA_RECALCULA_FECHA` e `COD_USR`.

### P3: O que representa o campo `FEC_TRATAMIENTO`?
**R:** `FEC_TRATAMIENTO` representa a data em que o processo massivo é realizado. O campo é obrigatório.

**R:** `TIP_SITU_FILTRO` representa a situação do movimento. Durante a operação, o campo pode receber o valor `2-Filtrando` e posteriormente o valor `3-Ya filtrado`. O campo é obrigatório.

### P5: O documento define todos os valores permitidos para `TIP_SITU_FILTRO`?
**R:** Não. O documento cita especificamente os valores `2-Filtrando` e `3-Ya filtrado`, indicando que esses valores dependem do momento da operação, mas não apresenta um catálogo completo de valores permitidos.

### P6: Para que serve `MCA_RECALCULA_FECHA`?
**R:** `MCA_RECALCULA_FECHA` é uma marca obrigatória que indica se deve ser tomada como base uma data já calculada ou se a data deve ser recalculada.

### P7: Qual campo informa a base usada para o recálculo de data?
**R:** O campo `TIP_FECHA_BASE` indica em qual data será baseado o recálculo da data. O campo não é obrigatório.

### P8: Como o usuário que atualizou um registro é identificado?
**R:** O usuário que atualizou a linha é identificado pelo campo obrigatório `COD_USR`.

### P9: Qual campo registra a data de atualização de uma linha?
**R:** O campo `FEC_ACTU` representa a data de atualização da linha. Conforme o documento, esse campo não é obrigatório.

### P10: O documento descreve métodos HTTP, APIs ou contratos JSON relacionados à tabela `G2000510`?
**R:** Não. O documento limita-se à visão técnica do modelo de dados e aos campos da tabela `G2000510`; não detalha métodos HTTP, APIs, contratos JSON ou integrações.

### P11: Qual é a finalidade de `TXT_ALIAS`?
**R:** `TXT_ALIAS` permite registrar o nome que se queira atribuir ao processo. O campo não é obrigatório.

### P12: Quais campos estão relacionados a processos de exceção, padrão e personalizados?
