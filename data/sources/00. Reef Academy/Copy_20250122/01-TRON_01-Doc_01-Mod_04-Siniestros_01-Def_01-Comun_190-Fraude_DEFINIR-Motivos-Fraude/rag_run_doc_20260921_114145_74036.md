## 2. Resumo Executivo & Contexto de Negócio

O documento define as propriedades necessárias para configurar distintos **Motivos de Fraude** para a companhia. O objetivo declarado é permitir o conhecimento das propriedades requeridas para a definição desses motivos.

A especificação apresenta propriedades gerais que identificam, descrevem, localizam por idioma, habilitam ou inabilitam e estabelecem a vigência de uma definição de motivo de fraude. As propriedades apresentadas são: código do motivo de fraude, idioma, nome do motivo de fraude, indicador de inabilitação e data de validade.

O conteúdo não descreve fluxos operacionais, contratos de API, métodos HTTP, persistência de dados, integrações, regras de validação detalhadas ou responsabilidades entre sistemas. Também não identifica formatos técnicos para código, idioma ou data.

## 4. Regras de Negócio, Especificações Funcionais & Processos

1. Uma definição de motivo de fraude deve possuir uma chave que identifique o motivo de fraude.
2. Uma definição de motivo de fraude deve possuir um código de idioma para os textos definidos.
3. Uma definição de motivo de fraude deve possuir uma descrição correspondente ao nome do motivo de fraude.
4. Uma definição de motivo de fraude deve indicar se está habilitada ou inabilitada para utilização.
5. Uma definição de motivo de fraude deve possuir uma data que determine quando a definição entra em vigor.

> **Nota de Análise:** O documento não informa se o código do motivo de fraude deve ser único, obrigatório, numérico ou alfanumérico. Também não especifica o formato da data de validade, valores permitidos para inabilitação ou códigos de idioma aceitos.
